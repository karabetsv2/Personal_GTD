# Личный GTD-бот в Telegram

Бот для управления задачами по методологии GTD (Getting Things Done):
быстрый захват идей в Inbox, разбор Inbox по шагам, списки Next
Actions/Waiting For/Calendar/Someday-Maybe, контексты (@метки), приоритеты
и дедлайны с напоминаниями. Бот личный, один пользователь, весь интерфейс
на русском. Ядро — алгоритмы, кнопки и FSM (aiogram 3); поверх него —
три опциональных ИИ-функции через OpenRouter (см. ниже), которые только
предлагают черновики и никогда не пишут в базу без подтверждения.

## Возможности

- Быстрый захват: просто напиши текстом задачу — она попадёт в Inbox.
  Если в тексте есть намёк на дату («завтра», «в пятницу», «15.08», «в 10»),
  бот предложит сразу запланировать.
- `/process` — пошаговый разбор Inbox: сделать сейчас / запланировать /
  в Next Actions с контекстом / в ожидание / отложить в Someday-Maybe /
  удалить.
- `/now` — что делать прямо сейчас, с фильтром по свободному времени
  (5/15/30/60/120 мин) и месту (дома/работа/вне дома/где угодно).
- `/plan сегодня|завтра|неделя` — список запланированных задач на период.
- `/do` — отметить задачу выполненной.
- `/all` — все задачи в любой категории на одном экране: фильтр по списку
  (Inbox/Next/Waiting/Calendar/Someday), правка или удаление прямо оттуда —
  удобно поправить, если задачу изначально отнесли не туда.
- `/done` — что уже сделано (сегодня/вчера/7 дней/всё время) с сортировкой
  по времени выполнения, приоритету или названию.
- `/edit`, `/delete` — изменить или удалить любую задачу; при удалении
  задачи с активным напоминанием бот спросит подтверждение.
- `/search текст` — нечёткий поиск по названию/описанию (опечатки, разный
  регистр — через rapidfuzz).
- Напоминания за час до дедлайна — через APScheduler, проверка раз в минуту.

### ИИ-функции (через OpenRouter, требуют `OPENROUTER_API_KEY`)

- **«Это проект»** в `/process` — задача превращается в проект
  (`projects`), а ИИ (модель `google/gemini-2.5-flash-lite` по умолчанию,
  температура 0) предлагает 3-5 следующих действий. Каждое — отдельным
  черновиком с кнопками Принять / Изменить / Отклонить; в базу пишется
  только то, что подтверждено. Можно пропустить ИИ и добавить действия
  вручную — в том числе если OpenRouter недоступен, бот сам предложит
  этот вариант.
- **`/balance`** — анализ баланса по спискам/контекстам за 30 дней
  (температура 1): где перекос, что зависло в Waiting For дольше 2 недель,
  сколько просрочек и т.д. Плюс автоматический такой же отчёт 1-го числа
  каждого месяца в 09:00. Если ИИ недоступен — присылает сырые цифры без
  анализа, а не молчит.
- **`/coach`** — свободный чат с ИИ-коучем по продуктивности (температура
  0.8), с системным промптом пользователя и актуальными данными задач в
  контексте каждого сообщения. Коуч только советует — не создаёт и не
  удаляет задачи напрямую. Выход — кнопка «⏹ Закончить» или `/cancel`.

Если `OPENROUTER_API_KEY` не задан или OpenRouter недоступен — все три
функции отвечают понятным сообщением и предлагают действовать без ИИ,
бот не падает.

## Модули

`config.py` · `db.py` · `states.py` · `keyboards.py` · `utils.py` ·
`handlers.py` · `ai_client.py` (единая точка обращения к OpenRouter) ·
`main.py` (точка входа).

## Схема БД

`tasks`, `contexts`, `task_contexts` (многие-ко-многим), `reminders`,
`settings`, `projects`. `tasks.project_id` связывает next-action-задачи
с проектом; `tasks.status_changed_at` — когда в последний раз менялся
статус (нужно для «висит в Waiting For дольше 2 недель» в `/balance`).
Обе колонки и `projects.description` добавлены поверх изначальной MVP-схемы
через безопасную additive-миграцию (`ALTER TABLE ... ADD COLUMN`) прямо в
`db.init_db()` — существующие данные на Volume не трогаются и не теряются.
Подробности — в комментариях `db.py`.

## Деплой на Railway

### 1. GitHub

1. Репозиторий уже подключён: `karabetsv2/personal_gtd`.
2. Смёрджи рабочую ветку в `main` (или настрой Railway деплоить именно с
   этой ветки — см. шаг 4). Убедись, что `main` — единственная default-ветка
   репозитория (Settings → Branches на GitHub).

### 2. Создание бота через BotFather

1. Открой в Telegram [@BotFather](https://t.me/BotFather).
2. Команда `/newbot`, задай имя и username (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`
   — это и есть `BOT_TOKEN`. Никому его не показывай.

### 3. Переменные окружения в Railway

В настройках сервиса (Variables) добавь:

| Переменная            | Значение                                | Обязательна |
|-----------------------|------------------------------------------|-------------|
| `BOT_TOKEN`           | токен от BotFather                        | да          |
| `DATABASE_PATH`       | `/data/gtd.db`                            | да          |
| `TIMEZONE`            | `Europe/Moscow` (или своя IANA-зона)      | нет (дефолт Europe/Moscow) |
| `LOG_LEVEL`           | `INFO`                                    | нет |
| `OPENROUTER_API_KEY`  | ключ с https://openrouter.ai/keys         | нет — без него бот работает, но `/balance`, `/coach` и разбивка проекта отвечают, что ИИ недоступен |

Модель и температуры для ИИ-функций задаются переопределяемыми
переменными с уже разумными дефолтами (`AI_MODEL_DEFAULT`,
`AI_MODEL_BREAKDOWN`/`AI_MODEL_BALANCE`/`AI_MODEL_COACH`,
`AI_TEMPERATURE_BREAKDOWN`/`AI_TEMPERATURE_BALANCE`/`AI_TEMPERATURE_COACH`,
`AI_REQUEST_TIMEOUT_SECONDS`, `COACH_HISTORY_LIMIT`) — добавлять их в
Railway нужно только если хочешь поменять что-то из этого, полный список
с дефолтами — в `.env.example`.

### 4. Volume — чтобы база не стиралась при редеплое

Railway при каждом деплое пересоздаёт файловую систему контейнера, поэтому
SQLite-файл **обязательно** должен лежать в примонтированном Volume:

1. В сервисе бота: **Settings → Volumes → New Volume**.
2. Mount path указать ровно: **`/data`**.
3. Убедиться, что `DATABASE_PATH=/data/gtd.db` (переменная из шага 3) —
   путь должен начинаться с того же `/data`, что и mount path тома.
4. Передеплой сервиса — файл `gtd.db` создастся внутри тома при первом
   запуске (`db.init_db()`) и будет переживать все последующие редеплои.

### 5. Автодеплой при пуше в main

1. **Settings → Source** — подключи GitHub-репозиторий `karabetsv2/personal_gtd`,
   если ещё не подключён (кнопка Connect Repo, авторизация GitHub App).
2. **Settings → Source → Branch** — выбери `main`.
3. Опция **"Auto Deploy"** включена по умолчанию — при каждом пуше в `main`
   Railway автоматически соберёт и передеплоит сервис (Nixpacks определит
   Python-проект по `requirements.txt`, команда запуска — `python main.py`
   из `Procfile`/`railway.json`).

### 6. Первый запуск

1. После успешного деплоя (Deployments → статус Success) открой бота в
   Telegram и отправь `/start` — это единственный шаг, который нужен для
   регистрации: бот сам сохранит твой `chat_id` в БД, чтобы знать, куда
   слать напоминания.
2. Проверь `/add`, `/process`, `/now` — если всё отвечает, деплой готов.
3. Если добавлял `OPENROUTER_API_KEY` — проверь `/balance` (должен прийти
   текстовый анализ, а не «ИИ недоступен») и в `/process` у любой задачи
   кнопку «📁 Это проект» → «🤖 Предложить разбивку с ИИ».

### Локальный запуск (для разработки)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # и вписать BOT_TOKEN
python main.py
```
